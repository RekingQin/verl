# 03 · 优化算法（各类 PO 算法实现细节）

> 返回索引：[README.md](README.md)

verl 把 RL 算法拆成两个可插拔注册表，位于 `verl/trainer/ppo/core_algos.py`：

## 3.1 优势估计器（Advantage Estimator）

注册机制：`@register_adv_est(name)` → `ADV_ESTIMATOR_REGISTRY`；`AdvantageEstimator` 枚举列出内置项。

```
 token_level_rewards / values / response_mask / index(uid)
        |
        v   get_adv_estimator_fn(name)
 +-------------------------------------------------------------+
 | gae          : 逐 token TD(λ) 回溯, 需 critic values        |
 | grpo         : 组内(同 prompt 的 n 个样本) 归一 (r-μ)/σ     |
 | grpo_vectorized / rloo_vectorized : 向量化加速版            |
 | dr.grpo      : grpo 关闭 norm_adv_by_std (不除 σ)           |
 | grpo_passk   : 仅组内最优样本得 (r_max - r_2nd) 优势        |
 | rloo         : leave-one-out 基线                           |
 | reinforce_plus_plus(_baseline) : RF++ / RF++-baseline       |
 | remax        : 贪婪 baseline 作为方差缩减                    |
 | opo / gpg / gdpo / optimal_token_baseline / tir_*           |
 +-------------------------------------------------------------+
```

实现要点（举例）：
- **GAE = Generalized Advantage Estimation（广义优势估计，[arXiv:1506.02438](https://arxiv.org/abs/1506.02438)）**（`compute_gae_advantage_return`，core_algos.py:216）：用 **TD(λ)** 在 critic 的 value 上做偏差-方差权衡。
  - 单步 TD 误差 `δ_t = r_t + γV_{t+1} - V_t`；λ 加权回溯 `Â_t = δ_t + γλÂ_{t+1}`（序列末尾反向累加）；`returns = Â + V`，最后 `masked_whiten(Â, response_mask)` 归一。
  - 超参物理意义：`γ`(gamma) 折扣未来回报；`λ`(lam) 在"低方差高偏差(λ→0，纯 TD)"与"高方差低偏差(λ→1，近 Monte-Carlo)"间插值。
  - observation token（`response_mask==0`，如多轮中环境注入的 token）上**跳过 TD 与 value**，只对生成 token 累计。
  - **是唯一需要 critic values 的估计器**——这正是 PPO 用 GAE、而 GRPO 系列免 critic 的本质区别。
- **GRPO**（`compute_grpo_outcome_advantage`，:268）：把整条响应的 reward 求和为标量 → 按 `index`（uid）分组 → `(score-μ)/(σ+ε)` → 广播到 token（乘 `response_mask`）。`norm_adv_by_std_in_grpo=False` 即 Dr.GRPO。
- **GDPO**（`compute_gdpo_outcome_advantage`，:362）：对多维 reward 各自组内归一后加权聚合，再全局 whiten，避免强信号淹没弱信号。
- **GRPO-PassK**（`compute_grpo_passk_outcome_advantage`，:472）：组内 top-2 之差 `r_max - r_second`，仅最优样本非零优势。
- 另有 `rloo`（:588）/ `rloo_vectorized`（:832）/ `remax`（:733）/ `reinforce_plus_plus`（:694）/ `opo`（:640）/ `gpg`（:769）/ `optimal_token_baseline`（:870）/ `tir_optimal_token_baseline`（:989）等，均以 `@register_adv_est` 注册到 `ADV_ESTIMATOR_REGISTRY`（:113）。

多轨迹场景由 `compute_advantage_for_multi_trajectories`（`verl/trainer/ppo/v1/utils.py:148`）处理：GRPO 仅用每个 session 最终输出参与组相对计算，再广播回同 session 其它输出。

## 3.2 策略损失（Policy Loss）

注册机制：`@register_policy_loss(name)` → `POLICY_LOSS_REGISTRY`：

```
 vanilla   : 标准 PPO clip 损失（ratio = exp(logπ - logπ_old)）
 gspo       : Group Sequence Policy Optimization（序列级重要性比）
 dppo_tv / dppo_kl : decoupled PPO（TV / KL 变体）
 clip_cov / kl_cov : 协方差裁剪（熵机制系列）
 geo_mean   : 几何平均比
 cispo      : clipped IS（MiniMax 系）
 sapo / gpg / bypass_mode
```

`PolicyLossFn` 统一签名：`(old_log_prob, log_prob, advantages, response_mask, loss_agg_mode, config, rollout_log_probs) -> (loss, metrics)`。
`agg_loss`（core_algos.py:1138，被 Driver 与 Worker 共用）按 `loss_agg_mode`（`token-mean` / `seq-mean-token-sum` / ...）聚合，配合可选参数 `loss_scale_factor`。

### actor loss 的三段组装（`workers/utils/losses.py:57` 起，组装 @ :120/:128/:140）

```
policy_loss = pg_loss                              # :120
            - entropy_coeff * entropy_loss         # :128 熵正则（鼓励探索）
            + kl_loss_coef   * kl_loss             # :140 KL-in-loss（约束偏离 ref）
```

**entropy loss（熵正则）**：`compute_entropy_loss`（core_algos.py:2067）对 logits 求逐 token 熵（`entropy_from_logits` 定义在 `utils/torch_functional.py:224`），再 `agg_loss` 聚合。以**减号**加入 loss（等价最大化熵），防止策略过早坍缩。开关 `actor.entropy_coeff`（默认 `0`，默认关闭）、`actor.calculate_entropy`。

### KL：两个完全独立的位置

**KL 估计器**（`kl_penalty` / `kl_penalty_forward`，core_algos.py:2147/2175，参考 [joschu KL-approx](http://joschu.net/blog/kl-approx.html)）：`k1`(=`kl`，`logπ-logπ_ref`) / `abs` / `k2`(=`mse`，`0.5Δ²`) / `k3`(=`low_var_kl`，默认，`exp(-Δ)+Δ-1` 低方差无偏)。后缀 `+`（如 `k3+`）用 straight-through 把 k2 无偏梯度绑到前向值上。

| 位置 | 函数 | 罚在哪 | 开关 |
|------|------|--------|------|
| **A. KL-in-reward** | `apply_kl_penalty`（ray_trainer.py:78） | 从 `token_level_rewards` 扣 `kl(old_log_probs, ref_log_prob)` | `algorithm.use_kl_in_reward` + `algorithm.kl_ctrl` + `algorithm.kl_penalty` |
| **B. KL-in-loss** | `losses.py:135` | 加进 actor policy loss：`+= kl_loss_coef * kl(log_prob, ref_log_prob)` | `actor.use_kl_loss`(默认 False) + `actor.kl_loss_coef`(默认 0.001) + `actor.kl_loss_type`(默认 low_var_kl) |

KL 系数由 `get_kl_controller` 管理：`FixedKLController`（固定）或 `AdaptiveKLController`（按目标 KL 自适应调节，[arXiv:1909.08593](https://arxiv.org/pdf/1909.08593.pdf)）。两位置可独立开关、互不影响——经典 PPO/RLHF 多用 A，GRPO 配方常用 B。

## 3.3 算法解耦总结

```
reward(标量/token) --[apply_kl_penalty(可选,A)]--[adv_estimator]--┬─> advantages ──→ actor loss (pg_loss)
                                                                  └─> returns     ──→ critic loss (value_loss, 仅 GAE)

old_log_prob, ref_log_prob, logits ─────────────────────────────→ actor loss (entropy / kl(B))

            actor loss = pg_loss - entropy_coeff*entropy + kl_loss_coef*kl(B) --> 反向
            critic loss = value_loss (仅 GAE 路径)                              --> 反向
```

新增算法通常只需：注册一个 adv_est 和/或 policy_loss，再在 yaml 里把 `algorithm.adv_estimator` / `actor.policy_loss.loss_mode` 指向它，无需改 Driver。详见 [06-自定义扩展方式.md](06-自定义扩展方式.md)。

## 3.4 新版本新增的算法/机制

- **DAPO 组过滤（filter_groups）**（`algorithm.filter_groups`，`AlgoConfig.filter_groups`）：按 `metric`（如 `seq_final_reward`）识别"reward 全部相同"的组并丢弃（`acc==0` 或 `acc==1` 的 prompt 组），减少无效样本与 off-policy 风险；配合 `max_num_gen_batches` / `max_inflight_gen_batches` 控制生成批调度。相关指标如 `training/filter_groups/*`（见 `ppo/v1/utils.py::MetricsAggregator`）。
- **偏好反馈 PPO（PF-PPO）**（`algorithm.use_pf_ppo` + `pf_ppo.reweight_method`）：按偏好对样本重加权（`pow` / `max_min` / `max_random`），核心函数 `compute_pf_ppo_reweight_data`（core_algos.py:2213）。
- **组内熵采样（GroupEntropy）** 等：通过 `get_policy_loss_fn` 组合与采样器（`ReplayBuffer`）联动。
