# 06 · 自定义扩展方式

> 返回索引：[README.md](README.md)

核心范式：**注册表（Registry）+ 配置切换（yaml/FQN），避免改 Driver**。verl 把每类可变点都做成"装饰器注册 + 按名取用"，新增能力 = 写一个函数/类 + 注册 + yaml 指向。

## 6.0 扩展点总览

| 扩展点 | 方式 | 关键位置 |
|--------|------|----------|
| 新优势估计器 | `@register_adv_est("name")` | `core_algos.py` |
| 新策略损失 | `@register_policy_loss("name")` | `core_algos.py` |
| **新 V1 trainer 模式** | `@register_trainer("mode")` 继承 `PPOTrainer`，`trainer.v1.trainer_mode` 指向它 | `trainer/ppo/v1/trainer_base.py` |
| 自定义 ReplayBuffer 采样器 | `trainer.v1.sampler.custom_sampler.{path,name}` | `trainer/ppo/v1/replay_buffer.py` |
| 新训练引擎后端 | `@EngineRegistry.register(model_type, backend, device)` 继承 `BaseEngine` | `workers/engine/base.py` |
| 新 dispatch 模式 | `register_dispatch_mode(name, dispatch_fn, collect_fn)` | `single_controller/base/decorator.py` |
| 新权重同步后端 | `@CheckpointEngineRegistry.register(backend)` | `checkpoint_engine/base.py` |
| 新模型(mcore) | mcore registry 注册 config/init/forward/weight converter | `models/mcore/registry.py` |
| 自定义 AgentLoop | 实现 AgentLoop + 配置 `agent_loop_manager_class`(FQN) | `trainer/main_ppo.py` / `experimental/agent_loop/` |
| 自定义 reward 管理器 | `@register("name")` 继承 `AbstractRewardManager` | `workers/reward_manager/registry.py` |

| 外部插件 | setuptools entry_point group `verl.plugins` | `verl/__init__.py` |
| 外部模块注入 | 环境变量 `VERL_USE_EXTERNAL_MODULES` | `verl/__init__.py` |

`load_class_from_fqn` / `load_extern_object`（`utils/import_utils.py`）支持通过全限定名/文件路径动态加载用户类——这是 manager / agent loop / reward 可插拔的关键。

## 6.1 新增优势估计器（最常见）

注册机制（core_algos.py:116）：`@register_adv_est(name)` 把函数塞进 `ADV_ESTIMATOR_REGISTRY`，Driver 通过 `get_adv_estimator_fn(name)` 按 `algorithm.adv_estimator` 取用。

```python
from verl.trainer.ppo import core_algos

@core_algos.register_adv_est("my_adv")          # 注册名
def compute_my_advantage(token_level_rewards, response_mask, index, **kwargs):
    # 输入: (bs, response_len) 的 token reward / mask, index 为 uid 分组
    scores = token_level_rewards.sum(-1)         # 整条响应得分
    # ... 你的归一/基线逻辑 ...
    advantages = scores.unsqueeze(-1) * response_mask
    return advantages, advantages                # 返回 (advantages, returns)
```

启用：`yaml` 里 `algorithm.adv_estimator=my_adv`，无需改 Driver。注意：不需要扩 `AdvantageEstimator` 枚举，直接用字符串名即可（源码注释明确说明）。

## 6.2 新增策略损失

注册机制（core_algos.py:53）：`@register_policy_loss(name)` → `POLICY_LOSS_REGISTRY`，由 `actor.policy_loss.loss_mode` 选择。统一签名（参考 `compute_policy_loss_vanilla`，:1278）：

```python
from verl.trainer.ppo.core_algos import register_policy_loss, agg_loss

@register_policy_loss("my_loss")
def compute_my_policy_loss(
    old_log_prob, log_prob, advantages, response_mask,
    loss_agg_mode="token-mean", config=None, rollout_is_weights=None,
):
    ratio = (log_prob - old_log_prob).exp()
    pg = -advantages * ratio                                   # 你的目标
    loss = agg_loss(loss_mat=pg, loss_mask=response_mask, loss_agg_mode=loss_agg_mode)
    return loss, {"actor/my_loss": loss.detach().item()}       # 返回 (loss, metrics)
```

启用：`actor_rollout_ref.actor.policy_loss.loss_mode=my_loss`。entropy/KL 等通用项由 actor loss 组装逻辑（见 [03-优化算法.md](03-优化算法.md) 3.2，`workers/utils/losses.py`）自动叠加，无需在此处理。

## 6.2b 新增 V1 Trainer 模式（`@register_trainer`）

V1 主链路把 trainer 也做成了可插拔注册表（`trainer/ppo/v1/trainer_base.py`）：继承 `PPOTrainer` 基类并注册，再在 yaml 里把 `trainer.v1.trainer_mode` 指向它，即可实现自定义训练循环（如新的流水线编排 / 新的 partial rollout 语义）：

```python
from verl.trainer.ppo.v1.trainer_base import PPOTrainer, register_trainer

@register_trainer("my_mode")
class PPOTrainerMyMode(PPOTrainer):
    def on_init_end(self): ...   # 覆盖生命周期钩子
    def on_step_end(self): ...
    def on_sample_end(self): ...
```

现有三种内置模式见 [13-异步训练方案对比.md](13-异步训练方案对比.md)：`sync` / `colocate_async` / `separate_async`。

## 6.3 自定义 reward

verl 有两条路径：

**(A) 函数式（最轻量，推荐先用这个）**——写一个普通 Python 文件，yaml 指向它（`reward.py:50 get_custom_reward_fn` 用 `load_extern_object` 动态加载）：

```python
# my_reward.py
def my_reward(data_source, solution_str, ground_truth, extra_info=None, **kwargs):
    return 1.0 if solution_str.strip() == ground_truth.strip() else 0.0
```
```yaml
reward:
  custom_reward_function:
    path: /abs/path/my_reward.py
    name: my_reward
    reward_kwargs: {}        # 会被 partial 合并进函数
```
支持同步/异步（`async def` 自动识别）。

**(B) 类式（需要状态/批处理逻辑）**——继承 `AbstractRewardManager` 并注册（registry.py:24）：

```python
from verl.workers.reward_manager.registry import register
from verl.workers.reward_manager.abstract import AbstractRewardManager

@register("my_rm")
class MyRewardManager(AbstractRewardManager):
    def __call__(self, data, return_dict=False):
        ...   # 返回 reward_tensor / extra_info
```
yaml `reward.reward_manager.source=register` + `name=my_rm`；也可走 `source=importlib` 直接按文件路径加载，不必预注册。

## 6.4 新增训练引擎后端

`@EngineRegistry.register(model_type=..., backend=..., device=...)` 注册，继承 `BaseEngine`（engine/base.py），实现 `init_model / forward_backward_batch / train_batch / infer_batch / get_per_tensor_param / load_checkpoint / save_checkpoint` 等接口。现有实现可作模板：

```python
@EngineRegistry.register(model_type="language_model", backend=["fsdp", "fsdp2"], device=["cuda", "npu"])
class FSDPEngineWithLMHead(FSDPEngine): ...

@EngineRegistry.register(model_type="value_model", backend="megatron")
class MegatronEngineWithValueHead(MegatronEngineWithLMHead): ...
```

注意三元组 `(model_type, backend, device)` 共同决定取哪个 Engine：`language_model`(actor/ref) vs `value_model`(critic)，backend ∈ fsdp/fsdp2/megatron/automodel/veomni/torchtitan/mindspeed，device ∈ cuda/npu。

## 6.5 新增权重同步后端

`@CheckpointEngineRegistry.register(backend)` 继承 `CheckpointEngine`（checkpoint_engine/base.py），实现 `prepare / build_topology / init_process_group / send_weights / receive_weights / finalize`（详见 [04-容错与恢复机制.md](04-容错与恢复机制.md) 4.2）。现有 naive/nccl/nixl/hccl/mooncake/kimi/delta（`delta_checkpoint_engine.py`，字节级 diff 增量同步）可参考，yaml `actor_rollout_ref.rollout.checkpoint_engine.backend=xxx` 切换。

## 6.6 外部插件与模块注入（不改 verl 源码）

verl 启动时（`__init__.py`）有两条"零侵入"扩展通道：

- **`VERL_USE_EXTERNAL_MODULES=pkg1,pkg2`**（:38）：import 时直接加载这些模块，触发其中的 `@register_*` 装饰器执行 → 完成注册。
- **`verl.plugins` entry_point**（:44）：在你自己的包 `pyproject.toml` 里声明 entry_point group `verl.plugins`，verl 启动会自动发现并 `load()`。由 `VERL_USE_EXTERNAL_PLUGINS`（`auto`/`none`/`pkg1,pkg2`）控制加载范围。

二者用途相同——让用户在**独立 pip 包**里注册自定义 adv/loss/engine/reward，无需 fork verl。

## 6.7 Recipe 与 experimental

- **`recipe/`**：完整算法配方（dapo / gvpo / spin / fault_recover …），通常继承现有 trainer 再覆写少量方法（如 `_balance_batch`），是"较大改动但仍复用主干"的范式。
- **`verl/experimental/`**：`agent_loop` / `fully_async_policy` / `one_step_off_policy` / `reward_loop` / `teacher_loop` 等计划合入主库的能力，通过 `verl.experimental.{module}` 使用；自定义 AgentLoop 经 `agent_loop_manager_class`(FQN) 注入。

---

> 选型建议：能用"注册函数 + yaml"解决的（adv/loss/reward 函数）就别动 Driver；需要新后端/新通信时用对应 Registry；要大幅改流程时用 recipe 继承；想以独立包分发就用 plugins/external modules。
