# 05 · 性能优化设计

> 返回索引：[README.md](README.md)

verl 的性能优化围绕一条主线：**变长序列 RL 训练中，如何让每张卡都吃饱、不空转、不浪费显存**。下面按"负载均衡 → 无填充计算 → 并行与显存 → colocate 显存复用 → 指标观测"展开。

## 5.1 序列长度负载均衡（`verl/utils/seqlen_balancing.py`）

**问题**：RL 生成的 response 长度天然变长，若按样本数平均分给各 DP rank，token 数（≈计算量）会严重不均，慢的 rank 拖垮整个 step（长尾等待）。

**解法**：`_balance_batch`（trainer/ppo/v1/trainer_base.py:1453）在 Driver 侧按"计算量"重排样本，使各 DP rank 的总 token（FLOPs）近似相等：

```
 ① 查 actor DP size（_query_dispatch_info，缓存进 _dispatch_info）
 ② _get_required_batch_multiple(dp_size):
        required = lcm(dp_size,
                       critic_mini_bsz * rollout.n,   # 若用 critic
                       actor_mini_bsz  * rollout.n)   # 若已过 critic_warmup
 ③ upsample_batch_to_divisible_size(batch, required, eos)  # 补齐到 required 倍数
 ④ workload = calculate_workload(seq_len)               # FLOPs 估计
 ⑤ get_seqlen_balanced_partitions(workload, k=dp_size, equal_size=True)
        # Karmarkar-Karp 最大差分法(LDM)，多路均分且每分区样本数相等
 ⑥ batch.reorder(扁平化分区)                            # 重排，dispatch 时自动均分
```

关键细节：
- **workload 估计**（`calculate_workload`）：用 `24576 * seqlen + seqlen²` 近似 attention FLOPs（前项线性=MLP/投影，后项平方=注意力），比单纯按 seqlen 更贴近真实计算量。
- **Karmarkar-Karp（`karmarkar_karp`，`utils/seqlen_balancing.py`）**：贪心地把"当前和最大与最小的分区"配对合并，得到近最优的多路均分；`equal_size=True` 保证每个 rank 拿到相同样本数（满足 dispatch 的整除前提）。
- **为什么先 upsample**：`upsample_batch_to_divisible_size`（padding_utils.py:127）追加合成 no-op 样本（`prompt_len=1/response_len=1`、reward 清零、打 `is_padding` 标记），把 batch 补到 `lcm(dp_size, mini_batch)` 的倍数，避免均分时产生碎片；padding 样本不参与 PPO/entropy/KL loss，metrics 也会按 `is_padding` 过滤。
- `log_seqlen_unbalance` 会记录重排前后的不均衡度指标，便于观测收益。

## 5.2 无填充计算 / 序列打包（zero-padding）

变长 batch 若 padding 到统一长度，padding token 会白白消耗算力与显存。verl 全链路尽量避免 padding：

- **存储层**：TransferQueue 用 **jagged nested tensor** 存变长序列（见 02 文档），不做全局 padding。需要规则张量时才 `to_padded_tensor` / `response_from_nested` / `response_to_nested`（`workers/utils/padding.py`）临时补。
- **训练前向（rmpad / remove padding）**：把整个 batch 的有效 token **拼成一条无 padding 的长序列**再算，结束后 `postprocess` 还原。
  - Megatron：`models/mcore/model_forward.py` 支持 **sequence packing（thd 格式）**，`preprocess_packed_seqs` / `postprocess_packed_seqs` 实现 rmpad。
  - FSDP：`use_remove_padding` 开关；**启用 Ulysses 序列并行（`ulysses_sequence_parallel_size > 1`）时必须同时开 `use_remove_padding`**（fsdp/transformer_impl.py:127，否则报错）。
- 收益：消除 padding token 的无效 FLOPs，同时让 5.1 的负载均衡能以"真实 token 数"为粒度。

## 5.3 并行与显存

### 训练并行后端

```
 FSDP / FSDP2     : ZeRO 风格分片（param/grad/optimizer 切到各 rank）
   device_mesh   : fsdp_size<0 或 >=world_size 时纯 fsdp 一维；
                   否则 (ddp, fsdp) 二维网格（create_device_mesh，fsdp/utils.py:40）
 Megatron-Core   : 3D+ 并行 —— TP(tensor) / PP(pipeline) / DP(data) / CP(context) / EP(expert)
   rollout 侧亦有 tensor_model_parallel_size / pipeline_model_parallel_size / data_parallel_size
```

### 序列并行（Ulysses）

`ulysses_sequence_parallel_size`：DeepSpeed-Ulysses 风格，**沿 seq 维切分**、用 all-to-all 重排做 attention，突破单卡长序列显存瓶颈。`ulysses_pad_and_slice_inputs` 负责按 sp_size 切分（见 transformers 各模型实现），必须配合 rmpad 使用。

### 显存优化手段

| 手段 | 配置 | 作用 |
|------|------|------|
| 参数 offload | `param_offload` | 非计算时把权重挪到 CPU |
| 梯度 offload | `grad_offload`（Megatron） | 梯度挪 CPU |
| 优化器 offload | `optimizer_offload` | optimizer state 挪 CPU（量最大） |
| 激活 offload | `enable_activation_offloading`（activation_offload.py:500） | 双缓冲异步把激活挪 CPU，与下一层计算重叠 |
| LoRA | `lora_rank>0` | 只训低秩 adapter，权重同步只传 delta |
| 大词表融合 | `linear_cross_entropy` / `entropy_from_logits_with_chunking` | 不物化 `(B,L,vocab)` logits（见 08 文档） |

offload 的开关/搬运由 Engine 统一管理：`is_param_offload_enabled` / `is_optimizer_offload_enabled`，进出计算时 `engine.to(device, model=?, optimizer=?, grad=?)`（engine/base.py:238）。train 模式搬 param+grad+optimizer，eval 模式只搬 param。FSDP2 的 CPU offload（`fsdp_config.offload_policy=True`）与梯度累积兼容。

## 5.4 Rollout-Train Colocate 与 Sleep/Wake

actor 训练与 rollout 推理引擎（vLLM/SGLang/TRT-LLM）**colocate 在同一组 GPU**——这是 HybridFlow "3D-HybridEngine" 的核心，避免训练/生成各占一套卡的浪费。代价是同一时刻只能跑一个，靠 sleep/wake 在两个角色间切换显存：

```
 rollout 阶段:  wake_up()  -> rollout 引擎占显存(weights+KV cache)生成
      |
 训练阶段:      sleep()    -> 释放 rollout 显存(weights+KV)，整卡让给 trainer
      |
 step 末尾:     update_weights() -> 把训练好的新权重灌回 rollout 引擎
```

显存释放有**两个粒度**（区别见 [04-容错与恢复机制.md](04-容错与恢复机制.md) 4.2.1）：
- **`sleep()`**（训练阶段）：释放权重 + KV cache（`sleep level=1`），需 `free_cache_engine=True`；事后 `wake_up` 重新占用。LoRA adapter 模式下 sleep 只释放 KV、base 权重留卡。
- **`release_kv_cache()`**（权重同步阶段）：只释放 KV、**保留权重 buffer 供 NCCL 原地写入**，比"释放权重再重分配"更快。

`free_cache_engine` 关闭时 sleep/wake 退化为 no-op（适合显存充足、不想付切换开销的场景）。

## 5.5 指标与吞吐（`verl/trainer/ppo/metric_utils.py`）

- **`compute_timing_metrics`（:611）**：输出每阶段 `timing_s/{name}`（秒）与 `timing_per_token_ms/{name}`（毫秒/token）。注意归一分母不同：`gen` 只按 response token，其余阶段（ref/values/adv/update_critic/update_actor）按 prompt+response 全 token。
- **`compute_throughout_metrics`（:655，注意拼写是 throughout）**：`perf/total_num_tokens`、`perf/time_per_step`、`perf/throughput = total_tokens / (time * n_gpus)`（每 GPU tokens/s）。
- **MFU（`utils/flops_counter.py` + `engine_workers.py`）**：`mfu = estimated_flops / promised_flops / world_size`；`estimate_flops` 按 batch 真实 seqlen 估算 FLOPs，`promised_flops` 取设备理论峰值；forward-only 阶段再 `/3`（无反向）。
- **`marked_timer`（`utils/debug`，底层 `simple_timer`）**：按颜色标注各阶段（gen/old_log_prob/ref/values/adv/update_actor…），与 `timing_raw` 字典对应，配合 profiler 可定位瓶颈。
- **`compute_variance_proxy_metrics`（:691）**：用 `E[A² × W(τ)]` 近似梯度方差，监控训练稳定性（需 actor 提供 `sum_pi_squared`）。另有 `compute_data_metrics`（:429）、`RolloutMoELoadBalanceMetricsAccumulator`（:340，MoE 负载均衡指标）。
