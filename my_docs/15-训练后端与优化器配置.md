# 训练后端（FSDP/Megatron）与优化器配置

> 解读基线：当前仓库 `feat/verl-learning` 分支，配置目录 `verl/trainer/config/`。

## 一、默认训练后端：是 FSDP，不是 Megatron

verl 训练**默认使用 FSDP（PyTorch FSDP/FSDP2），并非 Megatron**。

证据链（`ppo_trainer.yaml` 的 defaults 解析）：

```yaml
# verl/trainer/config/ppo_trainer.yaml
defaults:
  - model_engine: dp                                   # ← 默认后端选择器 = dp
  - actor@actor_rollout_ref.actor: ${model_engine}_actor   # → dp_actor
  - ref@actor_rollout_ref.ref: ${model_engine}_ref         # → dp_ref
  - critic@critic: ${model_engine}_critic                   # → dp_critic
```

- `model_engine/dp.yaml` → `model_engine: dp`
- `actor/dp_actor.yaml` → `strategy: fsdp`（注释里 TODO 切换到 fsdp2）
- `critic/dp_critic.yaml` → `strategy: fsdp`

即 `model_engine=dp` 这一层会把 actor / ref / critic 全部解析为 FSDP 配置（`strategy: fsdp`）。

> 对照：`actor/megatron_actor.yaml`、`critic/megatron_critic.yaml`、`ref/megatron_ref.yaml` 里才是 `strategy: megatron`，但默认不会被选中。

## 二、如何开启 Megatron

verl 用 `model_engine` 作为统一后端开关（一次性切换 actor/ref/critic）。

### 方式 1（推荐）：命令行覆盖 `model_engine`

```bash
python3 -m verl.trainer.main_ppo model_engine=megatron ...
```

这会把 actor/ref/critic 全部切换为 megatron 配置组。

### 方式 2：使用已废弃的 megatron 专用入口配置

```bash
# ppo_megatron_trainer.yaml 仅做兼容转发，内部就是 override model_engine: megatron
python3 -m verl.trainer.main_ppo --config-name ppo_megatron_trainer ...
```

```yaml
# verl/trainer/config/ppo_megatron_trainer.yaml（已标记 Deprecated）
defaults:
  - ppo_trainer
  - override model_engine: megatron
  - _self_
```

### 方式 3：脚本里按 backend 拼接 engine 配置（examples 常见写法）

examples / recipe 的 SFT 脚本里通过 `engine=${backend}` + `optim=${backend}` 切换，Megatron 还需补充并行度等参数：

```bash
MEGATRON_ENGINE_CONFIG="\
  engine=megatron \
  optim=megatron \
  engine.tensor_model_parallel_size=${TP_SIZE} \
  engine.pipeline_model_parallel_size=${PP_SIZE} \
  engine.virtual_pipeline_model_parallel_size=${VPP_SIZE} \
  engine.context_parallel_size=${CP_SIZE} \
  engine.use_mbridge=True"
```

> 其它可选后端：除 `dp`(fsdp) 与 `megatron` 外，配置目录还提供 `torchtitan`、`veomni`、`mindspeed`、`automodel`（nemo_automodel）等 `model_engine` 选项。

## 三、支持的优化器与默认值

不同后端各有自己的优化器配置类与构建机制，**默认优化器随后端不同而不同**：

| 后端 | 配置文件 / 类 | 默认优化器 | 备注 |
|------|---------------|-----------|------|
| FSDP（默认） | `optim/fsdp.yaml` / `FSDPOptimizerConfig` | **AdamW**（`torch.optim.AdamW`） | 动态导入，可换任意优化器 |
| Megatron | `optim/megatron.yaml` / `McoreOptimizerConfig` | **adam**（Megatron 原生 Adam） | 走 Megatron OptimizerConfig |
| Torchtitan | `TorchtitanOptimizerConfig` | AdamW | — |
| VeOmni | `VeOmniOptimizerConfig` | adamw | — |
| Automodel | `AutomodelOptimizerConfig` | AdamW（`torch.optim`） | 同 FSDP 动态导入机制 |

结论：**默认确实是 Adam 家族**——FSDP 默认是 `AdamW`（不是裸 `Adam`），Megatron 默认是 `adam`。

### FSDP 后端的优化器是「动态导入」的，可灵活替换

`verl/workers/config/optimizer.py::build_optimizer` 通过 `optimizer_impl`（模块路径）+ `optimizer`（类名）动态 import 实例化，因此理论上支持任意第三方优化器：

```python
# 默认：PyTorch AdamW
optimizer_impl: torch.optim
optimizer: AdamW

# TorchAO AdamW（bf16 随机舍入）
optimizer_impl: torchao.optim
optimizer: _AdamW
override_optimizer_config: {bf16_stochastic_round: true}

# BitsAndBytes 8bit AdamW（省显存）
optimizer_impl: bitsandbytes.optim
optimizer: AdamW8bit
```

说明：构建时只有当优化器名包含 `adam` 或 `ademamix` 时才注入 `betas`；其余 kwargs 通过 `override_optimizer_config` 透传。

### 关键默认参数（`optim/fsdp.yaml`）

```yaml
optimizer: AdamW
optimizer_impl: torch.optim
lr: 1e-3
weight_decay: 0.01
betas: [0.9, 0.999]
clip_grad: 1.0
lr_scheduler_type: constant   # 或 cosine
```

### 切换优化器示例（FSDP 后端命令行）

```bash
python3 -m verl.trainer.main_ppo \
  actor_rollout_ref.actor.optim.optimizer=AdamW8bit \
  actor_rollout_ref.actor.optim.optimizer_impl=bitsandbytes.optim \
  ...
```

## 四、混合精度训练：bf16 模型 + fp32 优化器如何配置

需求：模型用 bf16 做计算，但希望优化器状态（Adam 的 momentum/variance）保持 fp32 以保证数值稳定。

### FSDP 后端（默认）

verl FSDP 把精度拆成两层解耦（`verl/workers/engine/fsdp/transformer_impl.py`）：

1. **权重 / 优化器精度** ← `model_dtype` 决定。FSDP 分片的是这份参数，优化器直接建在其上：
   ```python
   # _build_module：训练时（forward_only=False）默认强制 fp32
   torch_dtype = torch.float32 if not self.engine_config.forward_only else torch.bfloat16
   ```
   `engine/fsdp.yaml` 默认 `model_dtype: fp32` → 这就是 master weights，**优化器状态天然是 fp32**。

2. **计算精度** ← `mixed_precision` 决定（autocast）。`mixed_precision=None`（默认）时：
   ```python
   param_dtype  = torch.bfloat16   # 前向/反向 bf16
   reduce_dtype = torch.float32    # 梯度 all-reduce fp32
   buffer_dtype = torch.float32
   ```

因此「bf16 计算 + fp32 优化器」= fp32 master weights + bf16 autocast，**是默认行为，通常无需额外配置**。显式写法：

```bash
# 关键：master weights / 优化器状态保持 fp32（默认）
actor_rollout_ref.actor.fsdp_config.model_dtype=fp32
# 计算精度 bf16（不写也默认 bf16）
+actor_rollout_ref.actor.fsdp_config.mixed_precision.param_dtype=bf16
+actor_rollout_ref.actor.fsdp_config.mixed_precision.reduce_dtype=fp32
+actor_rollout_ref.actor.fsdp_config.mixed_precision.buffer_dtype=fp32
```

> **避坑**：切勿把 `model_dtype` 设成 `bf16`，否则 FSDP 分片参数变 bf16，Adam 状态也退化成 bf16，失去 fp32 优化器意义。要 fp32 优化器就必须 `model_dtype=fp32`。
>
> **进阶（省显存）**：torchao 的 bf16 + 随机舍入主权重：
> `optimizer_impl=torchao.optim optimizer=_AdamW override_optimizer_config={bf16_stochastic_round: true}`。

#### mixed_precision 三个 dtype 字段含义（PyTorch FSDP `MixedPrecision` 语义）

| 参数 | 作用阶段 | 含义 | 默认 |
|------|---------|------|------|
| `param_dtype` | 前向/反向**计算** | all-gather 出完整参数后临时 cast 成的 dtype，matmul/激活都用它算 → 决定「算得快」 | `bf16` |
| `reduce_dtype` | 梯度**跨卡归约** | reduce-scatter / all-reduce 梯度时的累加精度，fp32 避免 bf16 尾数累加误差 → 决定「算得准」 | `fp32` |
| `buffer_dtype` | 模型 **buffer** | 非参数 buffer（norm running stats、rope 的 cos/sin 缓存、mask 等）被 cast 成的 dtype | `fp32` |

精度流转关系：

```
fp32 master weights (model_dtype=fp32, 优化器状态在此)
      │ all-gather + cast
      ▼
 param_dtype=bf16   ──► 前向/反向计算（bf16，快）
      │ 产生 bf16 梯度
      ▼
 reduce_dtype=fp32  ──► 跨卡梯度归约（fp32 累加，稳）
      │ 写回 fp32 梯度
      ▼
 fp32 优化器更新 master weights

 buffer_dtype=fp32  ──► 模型 buffer 按此精度（与计算流并行）
```

要点：
- `param_dtype`：唯一的「计算精度」开关。设 fp32 则退化为全精度计算，更慢更占显存。
- `reduce_dtype`：混合精度数值稳定性关键，多卡训练强烈建议保持 fp32（即便 param_dtype=bf16）。
- `buffer_dtype`：保护数值敏感的统计量/位置编码。纯 LLM（RMSNorm + 动态 rope）影响较小，保 fp32 更稳妥。

### Megatron 后端

思路与 FSDP 一致（低精度算 + 高精度更新），但配置入口分两处，且 fp32 主权重由 **distributed optimizer** 托管，而非 FSDP 的 `MixedPrecision`。

#### 1. 两个精度开关

| 开关 | 配置位置 | 作用 |
|------|---------|------|
| 计算精度 | `actor_rollout_ref.actor.megatron.dtype` | 模型前向/反向用 bf16 还是 fp16（`engine/megatron.yaml` 默认 `bfloat16`） |
| 优化器/主权重精度 | `actor_rollout_ref.actor.optim.*`（+ `override_optimizer_config`） | distributed optimizer 维护 fp32 main params 与状态 |

代码链路（`verl/workers/engine/megatron/transformer_impl.py`）：
```python
# _build_tf_config：dtype → 模型计算精度
self.param_dtype = PrecisionType.to_dtype(self.engine_config.dtype)   # 默认 bf16

# _build_optimizer：依据计算精度是否 fp16 选择优化器模式
optim_config = init_megatron_optim_config(
    self.optimizer_config,
    use_distributed_optimizer=self.engine_config.use_distributed_optimizer,  # 默认 True
    fp16=self.param_dtype == torch.float16,
)
```

#### 2. 默认 bf16 混合精度

`init_megatron_optim_config`（`verl/utils/megatron/optimizer.py`）bf16 分支仅设 `bf16=True, params_dtype=bfloat16`。配合 `use_distributed_optimizer=True`（默认），Megatron 分布式优化器（ZeRO-1 风格）自动维护：

- fp32 main params（master weights）
- fp32 优化器状态（Adam 的 `exp_avg` / `exp_avg_sq`）
- bf16 仅用于前向/反向计算与梯度

因此「bf16 模型 + fp32 优化器」是 Megatron 默认行为，**无需额外配置**；bf16 也不需要 loss scaling。

#### 3. fp16 模式（需 loss scaling）

设 `megatron.dtype=float16` 时走 fp16 分支：
```python
if fp16:
    optim_args.update({
        "bf16": False, "fp16": True,
        "params_dtype": torch.float16,
        "initial_loss_scale": 32768,   # 动态损失缩放，防梯度下溢
        "min_loss_scale": 1,
        "use_precision_aware_optimizer": True,
        "store_param_remainders": False,
    })
```
fp16 指数范围小易下溢，必须开 loss scaling；bf16 指数范围同 fp32，不需要。LLM 训练优先 bf16。

#### 4. 进阶：override_optimizer_config 控制优化器精度/显存

`optim.override_optimizer_config` 的任意字段会透传给 Megatron `OptimizerConfig`：

| 字段 | 作用 |
|------|------|
| `use_precision_aware_optimizer` | 精度感知优化器，main params/状态可低精度存储 |
| `store_param_remainders` | bf16 主权重 + 16bit 余数重建 fp32，省一半 main-param 显存（需 precision-aware） |
| `main_params_dtype` / `exp_avg_dtype` / `exp_avg_sq_dtype` | 单独指定 main params / Adam 一阶·二阶矩存储精度 |
| `optimizer_cpu_offload` / `optimizer_offload_fraction` | 优化器状态 offload 到 CPU，可按比例 |
| `overlap_cpu_optimizer_d2h_h2d` | CPU offload 时重叠 D2H/H2D 拷贝提速 |

大模型省显存常用组合（见 `recipe/dapo/test_dapo_qwen3next_80b_megatron.sh` 等）：
```bash
+actor_rollout_ref.actor.optim.override_optimizer_config.use_precision_aware_optimizer=True
+actor_rollout_ref.actor.optim.override_optimizer_config.optimizer_cpu_offload=True
+actor_rollout_ref.actor.optim.override_optimizer_config.optimizer_offload_fraction=1
+actor_rollout_ref.actor.optim.override_optimizer_config.overlap_cpu_optimizer_d2h_h2d=True
```

#### 5. FSDP vs Megatron 精度对照

| 维度 | FSDP | Megatron |
|------|------|----------|
| 计算精度开关 | `mixed_precision.param_dtype` | `megatron.dtype` |
| fp32 主权重来源 | `model_dtype=fp32` 的分片参数 | distributed optimizer 的 fp32 main params |
| 梯度归约精度 | `mixed_precision.reduce_dtype` | DDP/grad buffer（可经 `override_ddp_config` 调） |
| 优化器状态精度控制 | torchao `_AdamW` 等 | `use_precision_aware_optimizer` + `*_dtype` 系列 |
| 默认 bf16 + fp32 优化器 | 是 | 是 |

## 五、速查结论

- 默认后端：**FSDP**（`model_engine=dp` → `strategy: fsdp`），不是 Megatron。
- 开启 Megatron：命令行加 `model_engine=megatron`（或用兼容入口 `ppo_megatron_trainer`）。
- 默认优化器：FSDP=**AdamW**，Megatron=**adam**；FSDP 后端支持动态导入任意优化器（torch.optim / torchao / bitsandbytes 等）。
- bf16 模型 + fp32 优化器：FSDP 保持 `model_dtype=fp32`（默认）即可，计算精度由 `mixed_precision.param_dtype=bf16` 控制；Megatron 默认即为 fp32 main params，无需额外配置。
