## 2.1 数据：`DataProto`（`verl/protocol.py:318`）

verl 的"通用数据协议"，所有模块间数据传递的载体：

```
@dataclass
class DataProto:
    batch: TensorDict          # 等长张量批（GPU/CPU），如 input_ids/attention_mask/advantages
    non_tensor_batch: dict     # numpy object 数组，如 uid / raw_prompt / reward_model
    meta_info: dict            # 标量/配置，如 temperature / global_token_num
```

关键能力：
- **切分与聚合**：`chunk(n)`（:864）按 batch 维均分，`concat(list)`（:917）合并 —— 这是 `DP_COMPUTE_PROTO` dispatch/collect 的底层。
- **选择/重排**：`select` / `select_idxs` / `union`（与另一 DataProto 按 key 合并）。
- **迭代器**：`make_iterator(mini_batch_size, epochs, seed, dataloader_kwargs)`（:800）—— PPO mini-batch 多 epoch 更新的基础。
- **设备搬运**：`to(device)`，配合 tensordict 的非阻塞拷贝（NPU 上 `verl/__init__.py` 打了同步补丁防精度问题）。
- **自动 padding**：`DataProtoConfig.auto_padding` + `pad_dataproto_to_divisor`/`unpad_dataproto`，保证 batch 可被 DP world size 整除（环境变量 `VERL_AUTO_PADDING`）。

`DataProtoFuture`（:1174）：对 `ray.ObjectRef` 的封装，支持在结果未就绪时就声明 `chunk`/`concat`/`collect`，实现 Driver 侧的流水线非阻塞编排。

同步链路中进一步用 `KVBatchMeta`（来自 `transfer_queue`，回退实现见 `verl/utils/transferqueue_utils.py`）作为"轻量元数据句柄"，仅含 `keys / tags / partition_id / extra_info`，张量本体留在 TransferQueue。

### 2.1.1 `TensorDict`（同步链路行级容器，`verl/utils/tensordict_utils.py`）

来自 `tensordict` 库（verl 要求 ≥ 0.10），是同步链路里替代 `DataProto.batch` 的样本容器。结构 = `batch_size`（如 `[B]`；`[]` 表示只含元数据无 batch 维）+ 每个 key 一个 value，value 有四种类型：

| value 类型 | 含义 | 例子 | 切分行为 |
|------|------|------|----------|
| `torch.Tensor`（规则） | 等长张量（`torch.stack`） | 定长字段 | 按 dim0 切 |
| `torch.Tensor`（nested/jagged） | **变长序列**（`torch.nested.as_nested_tensor(layout=torch.jagged)`） | `input_ids/responses/position_ids/loss_mask` | 特殊 unbind 切分，**避免全局 padding（零填充来源）** |
| `NonTensorStack` | 按 batch 维的非张量列表 | `raw_prompt/reward_model/messages` | 按 batch 维索引 |
| `NonTensorData` | 标量级元数据，不随 batch 切分 | `global_steps/temperature` | 原样保留 |

一个 rollout 样本写进 TQ 时的字段（`_agent_loop_postprocess`）：`prompts / responses / input_ids / attention_mask / position_ids / response_mask(=loss_mask) / multi_modal_inputs / reward_score / extra_fields` + kwargs(`uid/session_id/global_steps`)。

配套算子（均在 `tensordict_utils.py`，对 nested tensor 做了特殊处理）：构造 `get_tensordict`/`list_of_dict_to_tensordict`；切分聚合 `chunk_tensordict`/`concat_tensordict`；选择/迭代 `index_select_tensor_dict`/`make_iterator`；DP 整除 `pad_to_divisor`/`unpad`；非张量存取 `assign_non_tensor*`/`get`/`pop`。

### 2.1.2 `TransferQueue`（外部独立包，控制面 + 数据面分离）

`pip install TransferQueue==0.1.8`（requirements.txt 锁定；源自 AsyncFlow 论文，Ascend 开源）。注意：V1 trainer 会检测是否 ≥ 0.1.9（`_tq_supports_checkpoint`），≥0.1.9 起支持 `save_checkpoint`/`load_checkpoint` 快照以配合断点续训（见 [04-容错与恢复机制.md](04-容错与恢复机制.md)），否则跳过该能力。verl 经 `transferqueue_utils.py` 桥接：

```
        控制面 (Control Plane)                数据面 (Data Plane)
 +----------------------------+      +-------------------------------+
 | TransferQueueController    |      | StorageManager (可插后端)      |
 |  - 跟踪样本(行)×字段(列)的   |      |  - SimpleStorage(默认 CPU mem)|
 |    生产/消费状态(metadata)  |      |  - Yuanrong/Mooncake/RayRDT   |
 |  - sub-sample 级可见性      |      |  SimpleStorageUnit = 2D 结构: |
 |  - 每个 task 独立消费历史    |      |    行=样本(global index)       |
 |  - 可插 Sampler             |      |    列=字段(field)              |
 |   (Sequential/GRPOGroupN)  |      |  可分布多节点                  |
 +----------------------------+      +-------------------------------+
```

- **Partition**：逻辑分区隔离 train/val/test 命名空间；verl 用 `partition_id="train"/"val"`。
- **KV 高层 API（Redis 风格，verl 用这层）**：`kv_put / kv_batch_put / kv_batch_get / kv_list / kv_clear`，支持**列级（field）细粒度访问**。
- **verl 里的编码**（`_agent_loop_postprocess`）：
  - **key 格式**：`{uid}_{session_id}_{index}`（uid=prompt 唯一 id，session_id=rollout.n 第几次采样，index=该 agent loop 第几个输出）。
  - **tags**：`{global_steps, status, prompt_len, response_len, seq_len}`。
  - **fields**：nested TensorDict（变长存储）。
- **两种元数据句柄**：`KVBatchMeta`（verl 主用，`keys/tags/partition_id/fields/extra_info`）与 TQ 原生 `BatchMeta`（`global_indexes/field_names/extra_info`），可互转。
- **tqbridge**（`verl/utils/transferqueue_utils.py`，被 `decorator.py:425` 的 `register` 套用）：`@register` 方法被自动包一层——进函数前 `KVBatchMeta → 真实 TensorDict`（`tq_client.async_get_data`），出函数后输出 `TensorDict` 写回 TQ 并返回更新后的 meta。张量只在 worker 内流动，Driver 只过 meta。

### 2.1.3 `ReplayBuffer`（verl 自实现，`trainer/ppo/v1/replay_buffer.py`）

> 注：原实现位于 `main_ppo_sync.py`，随 V1 重构迁移到 `trainer/ppo/v1/replay_buffer.py`，并提供 `ReplayBuffer`（同步）与 `ReplayBufferAsync`（异步）两个变体；`trainer.v1.sampler.custom_sampler` 可注入自定义采样器。

**不是 TQ 组件，也不是传统存 transition 的回放池**，本质是"TQ 元数据的轮询索引 + 同步屏障"；同步模式下无 off-policy 重用，异步模式下按 `max_off_policy_threshold` 容忍跨参数版本样本：

```python
class ReplayBuffer:
    partitions: dict[str, dict[str, dict]]   # partition_id -> {key: tags}  只存元数据!
    poll_interval: float                     # 轮询间隔，默认 1.0s
    lock: threading.Lock                     # 保护 partitions
    _stop_event: threading.Event
    poll_thread: threading.Thread            # daemon 后台线程
```

- `_poll_from_transfer_queue`（后台线程）：每 `poll_interval` 调 `tq.kv_list()` 拉元数据 → `add` 进 `partitions`；出错 `os._exit(1)`。
- `add` / `remove`：加锁增删元数据索引。
- `sample(partition_id, global_steps=None, batch_size=None)`：两参数互斥。
  - `global_steps` 模式：轮询直到本 step 无 `status=="running"`，再收集 `status=="success"` 的 key 成 `KVBatchMeta` 返回 → 同步屏障 + 成功样本筛选。
  - `batch_size` 模式：按数量采样（流式场景，供异步 trainer 使用）。
- `close()`：置 `_stop_event`、join 后台线程。

数据本体始终在 TransferQueue；ReplayBuffer 只维护"哪些 key 就绪/属于哪个 step/什么状态"的索引。

## 2.2 模型：Engine 抽象（`verl/workers/engine/`）

```
 BaseEngine (engine/base.py:30)  <--- EngineRegistry.register(key)
   |  interface:
   |    init_model / forward_backward_batch / train_batch / infer_batch
   |    get_per_tensor_param / load_checkpoint / save_checkpoint ...
   |
   +-- fsdp/        FSDP & FSDP2 训练引擎
   +-- megatron/    Megatron-Core 3D 并行引擎
   +-- automodel/   HF AutoModel
   +-- torchtitan/  TorchTitan

```

`workers/engine_workers.py` 中的 `ActorRolloutRefWorker`（:446）/ `TrainingWorker`（:76）把"角色逻辑"（actor/critic/ref）与"引擎后端"组合，是真正跑在 Ray actor 里的 Worker 类。`TrainingWorkerConfig`（在 `workers/config/` 定义）描述 model/engine/optimizer/checkpoint 四块配置。另有 `engine_workers_tinker.py` 提供 Tinker 式拆分训练原语（`TinkerTrainingWorker` / `TinkerActorRolloutRefWorker`）。

模型桥接（详见 [08-算子库构成与原理.md](08-算子库构成与原理.md)）：`verl/models/mcore/` 负责 HF config/weight ↔ Megatron-Core `GPTModel` 的双向转换。

## 2.3 通信：分层通信栈

```
 控制面：Ray RPC（actor.method.remote） + PlacementGroup
 训练面：torch.distributed（NCCL/HCCL） + FSDP/Megatron 集合通信
 数据面：TransferQueue（KV，零拷贝） / DataProto chunk-concat
 权重同步面：CheckpointEngine（trainer -> rollout，见 04 文档）
            后端：naive / nccl / nixl / hccl / mooncake / kimi / delta
```

Worker 启动时（`Worker.__init__`，worker.py:181）从环境变量读取 `WORLD_SIZE/RANK/MASTER_ADDR/MASTER_PORT`；`_setup_env_cuda_visible_devices` 统一处理 CUDA/HIP/ROCR 可见设备差异，兼容 Ray 的 `NOSET_VISIBLE_DEVICES`。
